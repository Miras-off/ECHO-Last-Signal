# Публикация ECHO в GitHub — инструкция

## Уже подготовлено в этом архиве

- Полный исходный код v2.1.2, карты TMJ, SVG, PNG, WAV/OGG и документация.
- Локальный Git-репозиторий в папке `.git` с **8 честно обозначенными импортами старых ZIP** и коммитом настройки GitHub.
- `.gitignore`, CI-тесты, шаблоны Issues и Pull Requests.
- Скрипт `tools/PUBLISH_TO_GITHUB.ps1` для первого push.

## Шаг 1. Создайте приватный репозиторий

Войдите на https://github.com/new под своим аккаунтом. Имя: `ECHO-Last-Signal`, видимость: **Private**. Не добавляйте README, `.gitignore` или лицензию — они уже в локальном репозитории. После создания запомните адрес, например `https://github.com/Miras-off/ECHO-Last-Signal`.

## Шаг 2. Распакуйте и отправьте

Распакуйте этот архив полностью, в том числе скрытую папку `.git`. Откройте PowerShell в корне распакованной папки, выполните:

```powershell
git status
git log --oneline -9
powershell -ExecutionPolicy Bypass -File .\tools\PUBLISH_TO_GITHUB.ps1 -Repository Miras-off/ECHO-Last-Signal
```

Скрипт откажется перезаписывать непустую удалённую ветку без явного вмешательства. Если авторизация спросит вход — используйте Git Credential Manager / браузер GitHub. Никогда не пересылайте пароль или personal access token в чат.

**Важно:** данные для входа в GitHub нужны только вашему локальному Git. Подключённый в ChatGPT GitHub App сейчас видит ваш логин, но **не имеет установленного доступа ни к одному репозиторию**. После создания репозитория настройте доступ для GitHub App через GitHub Settings → Applications → Installed GitHub Apps → Configure, затем выберите репозиторий ECHO (или нужные разрешённые репозитории).

## Шаг 3. Пригласите напарницу и преподавателя

В GitHub: Settings → Collaborators → Add people. Добавляйте **настоящие аккаунты** обоих людей. Каждый приглашённый должен принять приглашение. Для приватного репозитория проверьте, что доступ действительно предоставлен.

## Шаг 4. Создайте GitHub Project / Kanban

В GitHub Projects создайте доску `ECHO — лабораторные 8–15`. Добавьте статусы: `Backlog`, `To Do`, `In Progress`, `Testing`, `Done`.

Создайте Issues из `docs/GITHUB_ISSUES_RU.md`. Назначайте задачи только тому, кто действительно будет их выполнять. Не закрывайте Issues до фактической проверки.

## Шаг 5. Настоящие коммиты двух участников

Каждый участник входит **со своей учётной записи**, выполняет хотя бы несколько реальных доработок, фиксирует их в своей ветке и открывает PR. Укажите в PR доказательства: diff, тесты, скриншоты. Импорт старых архивов не считается работой двух студентов и не заменяет её.

## Шаг 6. Проверка на защите

Откройте `Code → Commits`, `Actions`, `Issues`, `Pull requests`, `Projects`. Продемонстрируйте, что исходники редактируются, коммиты содержательны, а тесты и материалы соответствуют лабораторным №10–15.
